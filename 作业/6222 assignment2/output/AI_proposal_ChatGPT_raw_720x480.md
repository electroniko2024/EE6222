# 特朗普静音合成视频教学与研究系统方案

## 1. 目标与基本假设

采用“参考图像驱动视频生成”的方案，使用冻结的预训练模型生成短片，再经过自动检查与人工审核，用于课堂演示或受控研究。

本方案是系统设计建议，尚未部署，也未完成实际性能测试。

| 项目 | 假设与要求 |
| --- | --- |
| 描绘对象 | 唐纳德·特朗普（Donald Trump） |
| 用途 | 教学演示、身份一致性与时间一致性研究 |
| 时长 | 6 秒 |
| 分辨率 | 720×480 像素，宽×高 |
| 帧率 | 恒定 8 fps |
| 总帧数 | 48 帧 |
| 场景 | 单人、固定镜头、中性背景 |
| 动作 | 眨眼、轻微转头等小幅动作 |
| 声音 | 文件不包含音频轨道 |
| 显著标识 | 每一帧均显示“AI-GENERATED — NOT REAL FOOTAGE”（AI 生成，并非真实影像） |

研究重点是识别身份漂移、面部变形、闪烁与动作不稳定。初期不进行身份专用微调。

## 2. 系统流程

```text
参考素材授权与来源检查
    ↓
选定参考肖像、批准的场景和动作
    ↓
参考图像驱动整段视频生成
    ↓
自动检查身份、时间一致性和文件规格
    ↓
人工审核：合格／拒绝并记录原因
    ↓
逐帧叠加显著合成标识、添加研究编号和来源信息
    ↓
导出检查：48 帧、720×480、8 fps、无音频轨道
    ↓
人工确认最终标识与内容后发布至批准的教学或研究渠道
```

保存素材、生成过程和审核结果之间的对应关系，便于复现实验和追溯问题。

## 3. 数据与来源管理

### 3.1 参考素材

初期收集约 20–40 张具有明确使用授权的参考照片，覆盖正面和轻微侧面，并尽量保持相近的年龄外观。公开可访问不等于可自由使用，必须逐项核查来源和许可。

每次生成使用一张审核通过的肖像作为条件输入，其余照片用于身份评估。本阶段不需要构建身份训练数据集。

### 3.2 划分与记录

- 按原始拍摄场次或事件划分参考集与评估集，近重复照片放在同一组。
- 保留若干独立场次作为评估集，避免只衡量输出与输入照片是否相似。
- 记录素材来源链接、许可、日期、允许用途，以及内部素材编号。
- 为输出记录参考图像、提示词、模型及软件版本、参数、随机种子、审核人和审核结论。
- 说明预训练模型原始训练数据的来源可能不完全透明；参考素材授权不能解决预训练数据的全部来源问题。

## 4. 模型、身份一致性与时间一致性

### 4.1 基线模型

可使用 [CogVideoX-5B-I2V](https://huggingface.co/THUDM/CogVideoX-5b-I2V) 作为具体基线。模型文档给出的示例生成 49 帧、720×480 像素的视频，并以 8 fps 导出。为满足严格的 6 秒交付规格，保留其中 48 帧。

采用前应核查 [模型许可证](https://huggingface.co/THUDM/CogVideoX-5b-I2V/blob/main/LICENSE) 是否符合具体研究及分发方式。以上参数来自文档，尚未在本项目硬件上实测。

### 4.2 身份一致性

- 使用一张审核通过的清晰肖像作为视觉条件。
- 固定年龄外观、服装、发型、光照和背景描述。
- 限制大幅转头、遮挡和复杂动作，以降低身份漂移。
- 通过独立评估照片检查整段视频中的身份相似度，而非仅检查首帧。
- 固定随机种子便于复现，但不能保证身份一致。

拒绝面部比例变化、头发或衣服不稳定、五官消失、明显身份漂移及大量非预期嘴部运动的片段。

### 4.3 时间一致性

整段视频联合生成，由图像条件和模型的时间建模共同维持连续性。初期采用固定镜头和小幅动作。

人脸对齐用于评估。不要将逐帧独立换脸或修复作为默认补救方式，因为这些处理可能引入新的闪烁与身份漂移。

## 5. 硬件与预算

| 项目 | 初期建议 |
| --- | --- |
| GPU | 单张 NVIDIA GPU，24 GB 显存；48 GB 提供更大余量 |
| 系统内存 | 64 GB |
| 存储 | 1–2 TB SSD |
| 显存优化 | CPU 卸载、VAE 分块；量化作为单独实验评估 |
| 本地采购预算 | 完整工作站约 2,000–3,500 美元 |
| 云端试验额度 | 预留 20 GPU 小时 |
| 云端费用假设 | 按每 GPU 小时 1–4 美元，约 20–80 美元 |

以上为规划额度，不是实时供应商报价；云端总成本还可能包含存储、数据传输和实例闲置费用。24 GB 是拟采用的起点，并非未经配置即可运行的保证。

先运行 5 个片段，测量运行时间、峰值显存、失败原因及每个审核通过片段的实际成本。成本应包含被拒绝的生成尝试。文档中的最低显存依赖卸载和优化配置，不能直接作为流畅运行的依据。

初期不微调。只有基线评估明确表明需要额外训练时，再单独制定训练数据、显存和预算方案。

## 6. 评估设计

### 6.1 实验规模与记录

使用若干审核通过的肖像、动作提示词和随机种子，生成约 30 个片段。保留失败样本及拒绝原因，不仅展示最佳结果。发布片段必须逐一通过人工审核。

### 6.2 身份指标

- 将各帧的人脸嵌入与独立保留的真实照片进行比较。
- 报告相似度中位数、最差帧相似度和随时间的漂移。
- 记录人脸检测失败或无法可靠评估的帧，不能静默排除。
- 使用真实同人、异人样本校准阈值，不设未经验证的通用余弦相似度阈值。

### 6.3 时间指标

- 在可见且非遮挡区域比较运动补偿后的感知差异。
- 检查面部关键点的异常跳动、背景闪烁和外观突变。
- 同时检查动作是否实际发生，避免指标把完全静止的输出误判为最佳结果。

### 6.4 人工评估

由两名审核者独立评价：

1. 是否能稳定识别为特朗普。
2. 面部结构是否完整。
3. 动作是否合理，是否存在身份漂移或明显闪烁。
4. 合成标识是否始终清晰可读。

记录评分分歧和最终处理决定。最终标注后的文件需再次审核。

### 6.5 导出检查

| 检查项 | 通过条件 |
| --- | --- |
| 帧数 | 恰好 48 帧 |
| 分辨率 | 720×480 像素 |
| 帧率 | 恒定 8 fps |
| 时长 | 6 秒 |
| 声音 | 不存在音频轨道 |
| 显著标识 | 每一帧均清晰可读 |
| 内容与审核 | 通过批准范围检查和人工审核 |

结果报告应列出实测通过率、拒绝原因、运行成本与局限，不能将身份保持描述为已获保证。

## 7. 误用控制

### 7.1 生成范围

界面只开放审核通过的中性场景和动作。排除伪造讲话、背书、新闻事件，以及容易使人误信特朗普实施过某项重要行为的内容。静音本身不能消除视觉误导风险。

### 7.2 输出标识与来源

- 生成后将显著的 AI 合成声明烧录进每一帧。
- 添加可见研究编号，将其对应到内部来源与审核记录。
- 在工具支持时附加签名来源元数据。
- 在缩放和重新压缩后测试标识可读性。

标识和来源元数据有助于识别与追溯，但无法阻止有意移除，不应将其宣传为不可删除的防护。

### 7.3 访问与发布

- 对生成入口实施身份验证、速率限制和日志记录。
- 对无标识中间产物限制访问；若未来训练身份专用权重，也应限制其访问。
- 只发布审核通过且带有显著标识的输出，并附实验目的和局限说明。
- 提供问题报告、撤下和纠正机制。

## 8. 初期研究问题与交付物

首个研究问题：**在小幅动作下，参考图像条件能多稳定地保持可辨认身份？这种稳定性如何随姿态和随机种子变化？**

建议初期交付物：

1. 素材来源与授权清单。
2. 可复现的模型、软件、提示词和参数记录。
3. 约 30 次生成尝试的完整实验记录。
4. 身份、时间一致性、人工审核和实际成本报告。
5. 经审核且逐帧标明合成属性的教学示例。
