# 明确标注的特朗普静音合成视频：教育与研究系统方案

## 1. 目标与假设

本系统面向受控的课堂演示和生成式视频研究，采用“参考图像 → 视频生成 → 质量评估 → 标注导出”的流程，研究人物外观保持、时间一致性和合成内容披露。

默认输出规格如下：

| 项目 | 假设 |
| --- | --- |
| 时长 | 5 秒 |
| 分辨率 | 1280 × 720（720p） |
| 帧率与帧数 | 恒定 24 fps，共 120 帧 |
| 音频 | 不包含音频轨道 |
| 人物 | 唐纳德·特朗普单人出镜 |
| 场景 | 通用摄影棚，单个连续镜头 |
| 动作 | 小幅转头、表情变化或简单手势 |
| 内容边界 | 不声称记录了真实事件、发言或背书 |
| 披露 | 每帧烧录“AI-GENERATED — NOT REAL FOOTAGE” |

第一版应限制镜头和动作复杂度，以便清楚区分身份保持与运动生成方面的问题。

## 2. 数据与模型

### 2.1 数据来源与管理

- 建立小规模、人工筛选的参考图像集，覆盖正面、四分之三侧面、不同表情和光照。
- 为每张图像记录来源、许可、使用限制和获取日期。公开可见不等于允许下载、训练或再分发；材料进入数据集前须确认用途符合相应条件。
- 按拍摄场次或事件划分开发集和评估集，避免同一组近似照片同时进入两者。
- 去除重复图像、严重遮挡、低质量图像和已有合成图像。
- 将原始材料与公开输出分开管理，并制定访问权限和保留期限。

### 2.2 模型选择

选择有明确 720p 支持、许可证符合项目用途的现有图像到视频模型，固定模型版本、权重、生成参数和随机种子。

第一阶段不进行人物身份训练，先检验参考图像条件是否足以维持外观。只有当评估持续发现相似度不足、且训练数据允许相应用途时，才考虑小型身份适配器，并重新评估其收益与风险。

具体模型和显存需求应在试运行中验证；本方案不将某个未经测试的模型视为已经满足全部要求。

## 3. 生成流程与一致性

1. **选择参考图像：** 使用经过审核的肖像，确定人物外观、构图和光照。
2. **设定提示词：** 描述通用背景、固定镜头和小幅动作，限制大角度转身、遮挡、快速运动和复杂手部动作。
3. **整段生成：** 使用具备时间建模能力的视频模型一次生成连续镜头，避免逐帧独立生成造成闪烁和身份漂移。
4. **适配输出规格：** 若模型输出稍长的受支持序列，可截取连续 120 帧；须核实源序列与目标帧率的关系，避免直接修改帧率导致动作速度改变。
5. **统一后处理：** 如需缩放，对整段序列使用一致处理。谨慎使用人脸修复，因为它可能改变人物相似度或引入逐帧闪烁。
6. **烧录披露：** 在图像处理完成后加入持续可读的标注，随后编码导出。
7. **检查最终文件：** 验证尺寸、恒定帧率、120 帧、5 秒时长、无音频轨道及逐帧标注。

### 3.1 身份一致性

通过固定参考图像、参考条件和受限动作保持人物外观。重点观察脸型、眼睛、鼻子、发型和肤色是否在时间上稳定。参考图像能够改善外观保持，但不能保证全片身份一致，仍须人工审核。

### 3.2 时间一致性

使用模型自身的时间条件约束，并控制镜头、光照和动作幅度。评估时区分合理运动与异常抖动，重点检查面部变化、头发闪烁、背景漂移、牙齿变形和手部异常。

## 4. 硬件与预算

建议先租用硬件完成试验，再决定是否购置设备。

| 资源 | 初始配置或预算假设 |
| --- | --- |
| GPU | 单张 80 GB 显存的 NVIDIA GPU，作为较大 720p 模型的保守起点 |
| 主机内存 | 64–128 GB |
| 工作存储 | 约 200 GB，按权重和中间文件实际占用调整 |
| 首轮计算配额 | 20 GPU 小时，用于环境配置、生成尝试和评估 |
| GPU 单价假设 | 2–8 美元／GPU 小时 |
| 首轮计算费 | 40–160 美元 |
| 存储预算 | 10–30 美元，按实际计费周期核算 |
| 初步预算合计 | 50–190 美元，不含人工、数据授权和可能的网络流量费用 |

上述金额是规划假设，不是实时供应商报价；20 GPU 小时也不代表已验证的产能。试运行须记录单次生成耗时、峰值显存、失败率和审核通过率，以计算“每条合格视频的成本”。

24 GB 显存的桌面 GPU 可能通过较小模型或节省显存的设置完成任务，但速度和质量须针对具体模型验证，不宜据此直接采购。

## 5. 评估设计

首轮可采用固定的 20 个提示词，每个提示词运行 3 个随机种子，共 60 次尝试。评估应覆盖全部尝试，不能只报告挑选后的成功案例。

| 维度 | 方法与关注点 |
| --- | --- |
| 身份相似度 | 对照保留的真实参考图像进行人工评分；人脸嵌入相似度仅作为辅助诊断 |
| 身份稳定性 | 检查逐帧身份相似度的变化，识别中途外观漂移 |
| 时间稳定性 | 结合预期运动，分析面部关键点抖动和运动补偿后的闪烁 |
| 视觉质量 | 人工检查脸部、头发、牙齿、手部、背景和运动自然度 |
| 披露有效性 | 检查最终文件每帧标注是否完整，并在常见播放尺寸下确认可读性 |
| 工程可行性 | 记录耗时、峰值显存、失败率、审核通过率及每条合格视频成本 |

增加一个对照条件：使用相同模型、提示词和种子，但不提供参考图像，以衡量参考条件带来的改善。

数值阈值应在人工评分的试验结果基础上制定，并在正式比较前固定。不要直接将某个人脸相似度阈值当作通用质量标准。可辨认出人物并不意味着视频质量合格；每条对外发布的视频都须人工批准。

## 6. 误用控制与发布

### 6.1 访问与生成限制

- 仅向已认证的研究人员或课堂成员开放，限制生成频率和批量请求规模。
- 第一版仅支持预先批准的人物参考和提示词范围。
- 拒绝伪造官方通告、背书、误导性的真实事件画面，以及移除合成披露的请求。
- 保存必要的生成参数、审核决定和来源记录，并按既定期限清理。

### 6.2 导出与公开传播

- 由导出环节强制烧录披露标注；对外分发仅提供已标注版本。
- 在发布页面、文件说明和配套教学材料中重复说明视频为合成内容。
- 条件允许时附加来源元数据或 Content Credentials，作为补充的溯源手段。
- 提供问题反馈和下架处理渠道，记录对外发布的版本。

烧录文字和元数据都可能被下游编辑者裁剪、遮盖或删除，不能视为防误用保证。系统应结合访问限制、逐条审核和来源记录降低风险。

## 7. 实施顺序与验收

1. **确认前置条件：** 核实参考材料、模型许可和允许的研究用途；存在问题时先确认处理方式，再继续使用相关材料。
2. **完成最小流程：** 跑通参考图像输入、连续镜头生成、标注和静音导出。
3. **执行固定试验：** 完成 60 次生成及对照评估，记录全部结果和资源消耗。
4. **确定质量门槛：** 根据试验制定审核标准，识别需要调整的模型、动作或数据条件。
5. **受控交付：** 对符合标准的结果逐条审核，只发布带有明确披露的视频。

验收目标是在可测量的成本下，稳定产出人物可辨认、时间连续、披露清楚的短视频，并确保每条公开结果经过审核。
